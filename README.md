# dsh-sidechat

[![Awesome DSH Plugin](https://awesome-dsh-plugin.com/badge.svg)](https://awesome-dsh-plugin.com/zh/p/yuhhhong/dsh-sidechat/)

中文 | [English](<./README.en.md>)

DeepSeek Harness（DSH）的侧边聊天插件。在主会话右侧栏打开带有当前背景快照的临时侧聊，用于调研问题、澄清细节或讨论支线，避免把临时讨论过程写入主会话上下文。

## 核心特点

- **背景快照与上下文隔离**：打开侧聊时截取主会话最近一个已完成轮次的背景快照；主会话后续推进不会自动同步。侧聊界面只展示新增对话，讨论过程和完成通知不自动回传主会话。
- **按需激活的托管子代理**：由 DSH 托管的可续聊子代理承载侧聊。新建空白标签只保存背景与配置，发送第一个问题后才启动子代理；收起右侧栏或切换主会话不会中断运行。
- **原生风格的统一输入区**：首问与续聊共用同一输入框，支持上传文件、粘贴图片、输入 `/` 搜索并调用技能（Skill），以及选择宿主权限预设、模型和思考强度。
- **引用到侧聊**：在主会话选中文字，点击原生「引用文本」旁的「引用到侧聊」，将内容放入目标侧聊草稿。引用与正文一起编辑，文字截断时悬停预览全文，可通过图标按钮、Backspace 或 Delete 逐条移除，允许手动发送纯引用；没有侧聊时会先创建空白标签。
- **运行中切换权限与模型**：新侧聊选中「默认」权限（`workspace-write + never`，可在工作区内修改，不请求审批），不继承主会话权限。首次提问前和回答过程中均可切换回「默认」或选择宿主权限预设、模型与思考强度。权限变更作用于当前侧聊后续的工具调用，模型与思考强度在下一次模型执行步读取，不中断已开始的操作。
- **提示词边界约束**：通过边界提示词将继承历史限定为参考背景，不续做主会话中的未完成任务；默认执行不修改状态的探索，禁止自行操作其他子代理，修改文件或向主会话发消息需用户在侧聊中明确要求。
- **生命周期清理与目录过滤**：在单次 DSH 运行期间刷新页面可恢复已发送消息和未关闭的侧聊，退出重启 DSH 后不恢复旧侧聊界面。点击标签 `×` 关闭后，插件停止后续执行、释放子代理资源，并从顶部「子智能体」目录中隐藏已结束的条目。

## 安装

**方式 1：通过插件市场安装。** 安装 [dsh-market](https://github.com/dsh-market/dsh-market/blob/main/README.zh.md#安装) 后，在 DSH 中打开「插件 → 插件市场」，在「发现」中搜索 `dsh-sidechat`，点击「安装」。

**方式 2：使用命令行从 GitHub 安装。** 在 DSH 的 Web profile 中执行：

```sh
dsh plugin --profile web add github:yuhhhong/dsh-sidechat
```

**方式 3：在 DSH 中手动添加。** 打开「插件」页，点击「添加插件」，填入仓库地址：<https://github.com/yuhhhong/dsh-sidechat>。

安装后重启 DSH 并刷新页面。

如需卸载：

```sh
dsh plugin --profile web remove dsh-sidechat
```

当前插件版本为 `0.1.15`，支持的 DSH 版本范围为 `>=0.2.2-rc.2 <0.3.0-0`。

## 使用方式

1. 在主会话中打开右侧栏的「开始」页，点击「新建侧边聊天」。
2. 在输入区提问、上传文件或粘贴图片、输入 `/` 选择技能，或调整权限、模型与思考强度。空白标签在发送首条消息时才启动托管子代理。
3. 回答期间可继续排队发送消息、停止本轮回答，或切换权限、模型与思考强度。
4. 讨论结束后，点击侧聊标签上的 `×` 关闭标签并释放子代理资源；若清理失败，标签会重新打开并显示错误原因。
5. 在主会话选中文字后点击「引用到侧聊」。展开且激活侧聊时引用进入当前标签；侧栏折叠或激活其他类型标签时，引用进入标签栏从左到右第一个可用侧聊。引用插在目标草稿保存的光标位置，有选区时插在选区末尾；引用后展开目标并聚焦输入区，等待手动发送。

## 子代理占用与交互规则

> **侧聊会占用子代理名额，用完请及时关闭。**

- **数量上限**：每个主会话最多保留 **3 个未关闭侧聊**（含创建中和正在关闭的侧聊）。输入区下方常驻显示提示及当前主会话的侧聊计数（如 `侧聊 2/3`）。
- **共享名额**：侧聊与同一子代理树中的其他任务共享宿主子代理名额。即使侧聊不足 3 个，宿主名额也可能已被其他子代理任务占满。
- **驻留与释放**：为避免子代理自然结束后自动向主会话投递完成通知，已激活的侧聊在打开期间会保持托管实例驻留。收起侧栏、切换标签、切换主会话或仅停止本轮回答，都不会释放子代理名额；用完请点击标签 `×` 关闭。
- **标签命名**：标签固定显示创建时的「侧边聊天 n」（`n` 为创建时当前主会话未关闭侧聊数量加 1），已有标签不重新编号，发送消息或子会话标题变化均不改写标签名。
- **草稿与恢复**：页面刷新可恢复本次 DSH 运行中的侧聊身份与已发送消息；未发送的文字和附件草稿仅在当前页面运行期间保留，切换标签不丢失。
- **日志与目录**：顶部「子智能体」目录仅显示未关闭的侧聊，关闭清理成功后自动隐藏并同步数量。宿主底层会话日志继续保留，默认历史搜索仍可命中侧聊记录。

## 本地开发

运行语法检查与测试：

```sh
npm run check
npm test
```

修改 Host 或客户端代码后，需退出并重启 DSH 以重新发布并加载插件；重启会结束当次运行中的临时侧聊。

| 文件 | 用途 |
| --- | --- |
| [index.js](<./index.js>) | 宿主插件入口，注册子代理提供方、Remote 接口与 `sidechat_manage` 工具 |
| [client.js](<./client.js>) | Web 客户端入口，负责右侧栏标签、历史边界裁切、统一输入区与子智能体目录过滤 |
| [src/host/controller.js](<./src/host/controller.js>) | 侧聊状态管理、托管子代理生命周期、模型与权限切换及上下文租约 |
| [src/host/background.js](<./src/host/background.js>) | 主会话背景快照截取与侧聊边界提示词生成 |
| [src/host/input.js](<./src/host/input.js>) | 模型配置校验、文件与图片附件暂存及续聊内容转换 |
| [src/host/remote.js](<./src/host/remote.js>) | Typert Remote 接口定义与请求参数校验 |
| [cordis.patch.yml](<./cordis.patch.yml>) | DSH 插件加载补丁配置 |


## 持续集成与发布

分支推送和 PR 会触发 [CI 工作流](<./.github/workflows/ci.yml>)，使用 Node.js 24 运行语法检查和测试。检查使用 Node.js 内置模块，无需安装依赖；需要 Electron 与 DSH 安装目录的宿主集成测试在普通 Node.js 环境中跳过。

发布流程参考 dsh-skill-status：推送 `v` 前缀标签后，[发布工作流](<./.github/workflows/release.yml>) 核对标签与 [package.json](<./package.json>) 的版本，从 [更新日志](<./CHANGELOG.md>) 提取说明，并运行语法检查和测试。全部通过后自动创建 GitHub Release，不附带压缩包。

发布前同步更新包版本、中英文 README 中的当前版本，并在更新日志中写入对应版本的说明，提交后再创建标签。标签与包版本不一致，或更新日志对应段落缺失、为空时，发布会失败。

```sh
git tag -a v0.1.15 -m "发布 v0.1.15"
git push origin main
git push origin v0.1.15
```

以上以当前版本为例，发布后续版本时替换版本号。可在发布前预览 Release 正文：

```sh
node scripts/release-notes.mjs
```
